## What Kelviq handles

| Area | What you get |
| --- | --- |
| **Tax and compliance** | Kelviq is the seller of record. We calculate, collect, and file sales tax, VAT, and GST, and handle fraud and chargebacks. |
| **Checkout** | Hosted checkout with plan picker, trials, discounts, business purchases, and local payment methods. |
| **Pricing** | Flat, per seat, usage-based, tiered, volume, credits, pay as you go, one-time, or a mix. |
| **Entitlements** | Turn features on per plan, set usage limits, and check what each customer can access with one SDK call. In the dashboard, these are **Features & limits**. |
| **Usage** | Report usage as it happens. Kelviq counts it, resets it, and bills overage. |
| **Subscriptions** | Upgrades, downgrades, proration, and cancellations, plus a customer portal. |
| **Digital products** | File downloads, license keys, and links delivered after purchase. |
| **Local pricing** | Prices by country in 135+ currencies. |

Pricing changes happen in the dashboard or the CLI, not in your code. Your app checks features, not plan names, so moving a feature between plans needs no deploy.

## How it fits together

1. Create **products**, **plans**, and **features** in the dashboard or with the CLI.
2. Send customers to **checkout**. Kelviq takes the payment and the tax.
3. Your app **checks access** and **reports usage** with the SDK.
4. Kelviq bills renewals and overage, and **pays you out**.

## FAQ

<AccordionGroup>
  <Accordion title="Do I need to handle webhooks?">
    No. Your app can ask Kelviq for a customer's access at any time, so you don't need to keep subscription state in your database. [Webhooks](/guides/webhooks) are there if you want events in your own systems.
  </Accordion>
  <Accordion title="What if Kelviq can't be reached?">
    The Node and Python SDKs return the last known access for a customer and retry usage reports later. See [When the Entitlement API is unavailable](/product-catalog/entitlements#when-the-entitlement-api-is-unavailable).
  </Accordion>
  <Accordion title="Can I test without real payments?">
    Yes. The [sandbox](/guides/sandbox) is a separate environment with its own keys and test cards.
  </Accordion>
  <Accordion title="What does it cost?">
    A percentage of each transaction, with no monthly fee. See [Fees](/getstarted/fees).
  </Accordion>
  <Accordion title="Do I need a Stripe account?">
    No. You can sell and get paid without one, including in countries where Stripe doesn't offer its own accounts, such as India. Payouts go through a payout account you set up in Kelviq. See [Payouts](/payouts/overview#do-i-need-a-stripe-account).
  </Accordion>
  <Accordion title="Can I use my own Stripe account?">
    Yes, if you'd rather stay the merchant of record yourself. You then handle your own tax and compliance. See [Merchant of record](/getstarted/merchant-of-record).
  </Accordion>
</AccordionGroup>
